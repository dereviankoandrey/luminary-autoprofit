# Developer Playbook Membership — Month 1 Starter Backlog

## Purpose
Prove the first 4 weeks of the membership can be outlined in one sitting without drifting into custom consulting.

## Week 1 — Fast Deal Triage OS
**Playbook:** Turn raw opportunities into a fast GO / REVIEW / NO-GO workflow.  
**Template asset:** deal-screen intake form + scoring rubric.  
**Member outcome:** screen inbound deals faster and kill weak deals earlier.  
**Autonomous production notes:** can reuse underwriting logic, beta packet framing, and fixed scoring templates.

## Week 2 — Austin Signal Brief Workflow
**Playbook:** Build a repeatable local market-intel issue from public sources.  
**Template asset:** signal collection sheet + issue assembly checklist.  
**Member outcome:** maintain a weekly local watchlist without bespoke analyst work.  
**Autonomous production notes:** uses the Austin subscription spec, template, and source map already created.

## Week 3 — Diligence Checklist Engine
**Playbook:** Standardize document review, red-flag capture, and follow-up questions.  
**Template asset:** diligence checklist + red-flag log.  
**Member outcome:** reduce missed issues and speed up handoffs across deals.  
**Autonomous production notes:** highly templatizable and easy to package into a repeatable format.

## Week 4 — Agent Ops for Operators
**Playbook:** Use AI agents for recurring research, packaging, and operating tasks.  
**Template asset:** agent task brief + QA checklist.  
**Member outcome:** delegate repetitive work without losing control of output quality.  
**Autonomous production notes:** aligns directly with the membership's differentiation around operator-grade automation.

## Pass / Fail Check
This backlog passes if:
1. the first month feels coherent,
2. each week has a clear member outcome,
3. each issue can be produced from a fixed template,
4. and the offer feels more like a productized operating system than a vague content subscription.
