# Development Update Ingestion Log

**Last updated:** 2026-04-20 05:00 UTC  
**Purpose:** capture dated live project updates once, then push them cleanly into the operating sheet, capital tracker, top-3 briefing pack, and execution board.

## Why this exists
The business now has strong snapshot documents for:
- priorities
- project status
- capital/outreach tracking
- weekly review
- top-3 project briefs

What was still missing was a dated intake log that preserves **what changed, when it changed, who reported it, and where it still needs to be propagated**. Without that, live updates can get lost between conversations and tracker maintenance.

## Use Rule
For any meaningful project or counterparty update:
1. add a dated entry here first
2. mark which source the update came from
3. list only verified facts
4. note which downstream documents still need updating
5. close the propagation checklist only after the other trackers are updated

## Suggested operating rhythm
- Log updates as they happen or immediately after a review call
- During weekly review, clear any unchecked propagation items
- If the same project changes multiple times in a week, add multiple dated entries rather than overwriting history

## Why this matters
The other documents show the current state. This file preserves the update trail and makes sure new facts actually flow into the system instead of staying trapped in messages or memory.
