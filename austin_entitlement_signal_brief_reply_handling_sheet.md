## Core rule
Do not over-answer.

Each reply should move the contact to exactly one next step:
1. send sample
2. confirm workflow fit
3. offer pilot
4. route to intake/setup
5. log not now / not fit

## Fast branch map
- **"Yes, send it"** -> send sample + 1 question
- **"What is this exactly?"** -> send one-paragraph explanation + sample offer
- **"Looks useful"** -> ask workflow-fit question, then offer pilot
- **"How much is it?"** -> answer price directly + restate buyer fit
- **"Can my team use it?"** -> position team plan
- **"We already monitor this"** -> test whether current monitoring is manual / fragmented
- **"Not now"** -> preserve future follow-up date
- **"Need something broader"** -> log scope mismatch
- **"Can you do custom property research?"** -> decline custom scope, restate product boundary

## What counts as positive signal
- asks for sample
- names a current monitoring pain
- asks about team use
- asks about price without rejecting relevance
- says they already track this but admits the process is manual

## What counts as weak signal
- wants general Austin news
- wants one-off custom research only
- has no active Austin workflow
- says useful in theory but cannot name a user or buyer
